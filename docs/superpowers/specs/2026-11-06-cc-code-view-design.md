# CC Code View 設計書

作成日: 2026-11-06

## 目的

Rust と gpui で作る macOS 用のコードリーディング専用ビューアー。
GitHub からクローンしたローカルリポジトリを登録すると、ローカルの `claude -p` が解析し、大きなリポジトリの全体像と読む順番を示す。
Rust の起動速度、小さなバンドルサイズ、少ないメモリ消費を活かす。

コンセプトは「コードベースの星図を、AI の案内で航海する」。

## 初版の範囲

### 含むもの

- リポジトリの登録と一覧（フォルダ選択、ドラッグ&ドロップ）
- 星図、ガイドツアー、コード表示、ファイル検索、全文検索
- AI による解析、モジュールごとの深掘り、モデル選択

### 含まないもの

AI チャット、コード編集、差分表示、LSP 連携、Mac 以外への対応、公証済みの配布、日本語以外の UI と AI 出力。

## 体験

### 登録

1. 利用者がフォルダを選ぶかドラッグする。Git リポジトリでなければ理由を表示して登録しない。
2. Rust による集計が走り、数秒で星が現れる。この段階では AI を使わない。
3. 星図の上に「AI 解析を開始」とモデル選択を表示する。Enter で開始する。
4. 解析の進捗は星図に反映し、完了すると星座名と説明が灯る。

AI 解析は利用枠を消費するので、開始前に必ずモデルを確認できるようにする。

### 星図

| 要素 | 表すもの |
|---|---|
| 星座 | モジュール（AI 解析の前はディレクトリ構造から仮に分割する） |
| 星 | ファイル |
| 星の大きさ | コード行数 |
| 星の明るさ | Git の変更頻度（直近 1 年のコミット数） |
| 線 | ファイルまたはモジュール間の依存関係 |

- 星の配置は決定的に計算し、同じ入力からは同じ配置を返す。再解析しても地形が変わらないようにする。
- ズームは段階的に詳細化する。遠景では星座のみ、中景で主要ファイル名、近景で全ファイル名を出す。
- 星をクリックするとコード表示が開く。
- ワークスペースは星図とコードの 2 ペイン構成で、コードを開いていないときは星図を全面に表示する。

### ガイドツアー

AI が作る順序付きの停留所の列。各停留所はファイル、行範囲、タイトル、解説を持つ。

- `←` `→` で移動する。星図のカメラ、コードのスクロール、解説の表示が同時に動く。
- 再開時は前回の停留所から始める。

### コード表示

- 行単位の仮想スクロール。100 万行のファイルでも開ける。
- 2 MB を超えるファイルはハイライトを省略する。バイナリは種別とサイズのみ表示する。
- tree-sitter によるハイライトとシンボル一覧。対応言語は Rust、TypeScript、JavaScript、Python、Go。
- シンボル名の一致による簡易定義ジャンプ。候補が複数あれば一覧から選ぶ。
- `⌘[` `⌘]` で移動履歴を戻る、進む。

### 検索

- `⌘P`: ファイル名のあいまい検索。
- `⌘⇧F`: リポジトリ全体の全文検索。`ignore` と `grep` クレートを使い、インデックスは作らない。

### 深掘り

星座を開くと、保存済みの解説があれば表示する。
なければ「解説を生成」ボタンとモデル選択を表示し、押されたときだけ `claude -p` を実行する。

### モデル選択

AI 処理を実行するすべての場所（初回解析、再解析、深掘り）で選べるようにする。

- 選択肢は「Claude の既定」「Fable」「Opus」「Sonnet」「Haiku」。`fable`、`opus`、`sonnet`、`haiku` の別名を `--model` に渡すので、各系列の最新モデルが使われる。「Claude の既定」では `--model` を付けない。
- 初期値は最後に使ったモデル。初回は「Claude の既定」。設定はアプリ全体で 1 つ保持する。
- 結果には使ったモデルを記録して表示する。別のモデルで作り直すときは再解析を実行する。

## 構成

Cargo ワークスペースを 3 つのクレートに分ける。`core` と `ai` は gpui に依存せず、単体でテストできる。

```
crates/core  走査、シンボル抽出、依存グラフ、Git 変更頻度、星の配置、全文検索、保存
crates/ai    claude の実行、プロンプト生成、進捗の解釈、出力の検証
crates/app   gpui の画面。部品は世界観に合わせて自作する
```

依存の向きは `app → ai → core`。

### 主なデータ

```
RepoIndex  コミット SHA、ファイル一覧（パス、言語、行数、変更頻度）、シンボル、依存辺、星の座標
Analysis   コミット SHA、使用モデル、モジュール（名前、説明、所属ファイル）、ツアー（停留所の列）
DeepDive   モジュール ID、コミット SHA、使用モデル、解説、重要ファイル
Settings   登録リポジトリ、最後に使ったモデル、ツアーの位置
```

### 保存

保存先は `~/Library/Application Support/cc-code-view/`。JSON で保存し、書き込みは一時ファイルからのリネームで行う。
登録したリポジトリには何も書き込まない。
HEAD が保存時と異なる場合は「解析が古い」と表示する。古い解析も表示は続け、消えたファイルを指す停留所だけ無効にする。

## 処理の流れ

1. `core` が `.gitignore` を尊重して走査し、シンボルと依存を並列に抽出する。Git の変更頻度を加えて `RepoIndex` を作る。
2. `app` が星図を描く。
3. 利用者が開始すると、`ai` が `RepoIndex` を圧縮した骨格（ディレクトリ、主要シンボル、依存、変更頻度）をプロンプトに入れて `claude -p` を実行する。
4. Claude は `Read`、`Grep`、`Glob` で必要な箇所を読み、結果を指定の JSON ファイルに書く。
5. `ai` が検証して `Analysis` を保存し、`app` が星図に反映する。

重い処理はすべて gpui のバックグラウンド実行器で動かし、描画スレッドを止めない。

## AI 実行とセキュリティ

クローンしたリポジトリは信頼できない入力として扱う。`.claude/`、`.mcp.json`、フック、コード中の指示で利用者の環境を操作させない。

### 実行コマンド

```
claude -p <prompt>
  --restricted --strict-mcp-config
  --tools Read,Grep,Glob,Write
  --permission-mode dontAsk
  --allowedTools Read,Grep,Glob,Edit(/<出力ファイル>)
  --settings '{"permissions":{"blockReadsOutsideWorkingDirectories":true,"blockWritesOutsideWorkingDirectories":true}}'
  --output-format stream-json --verbose
  --add-dir <リポジトリ>
  [--model <モデル>]
```

作業ディレクトリは実行ごとの空の一時ディレクトリとし、出力ファイルだけをそこに置く。

### 実装時に検証すること

次の項目は結合テストとして実機で確認し、一つでも満たさなければスナップショット方式（`.claude/`、`.mcp.json`、`CLAUDE.md` などを除いた一時コピー）に切り替える。

- 悪意のある `.claude/settings.json` のフック、`.mcp.json`、`CLAUDE.md` が読み込まれないこと
- リポジトリ外のファイルを読めないこと
- 出力ファイル以外に書けないこと
- `--restricted` の下でも利用者の認証で動作すること
- `dontAsk` のまま出力ファイルへ書き込めること

### 出力の検証

- スキーマの一致に加え、参照するファイルと行範囲が `RepoIndex` に存在すること、パスがリポジトリ外を指さないことを確認する。
- 不正な参照は該当項目だけ除外する。JSON として不正なら 1 回だけ再試行する。
- AI の文章は書式なしのテキストとして表示し、リンクやコマンドとして解釈しない。

### 環境

Finder から起動すると `PATH` が不足するので、`cc-auto-review` と同様にログインシェルから `PATH` を取得する。

## エラー処理

| 状況 | 動作 |
|---|---|
| `claude` が未導入、または `claude --help` に `--restricted` が無い古い版 | AI 機能を無効にし、導入方法を表示する。星図とコード表示は使える |
| AI 解析の失敗、タイムアウト（10 分）、利用枠の上限 | 仮の星図を残し、理由と再試行ボタンを表示する |
| AI 解析中の中断 | プロセスを終了し、前回の解析があれば維持する |
| リポジトリの移動、削除 | 一覧で「見つかりません」と表示し、場所の再指定か登録解除を選ばせる |
| 読めないファイル、不正な文字コード | そのファイルだけ理由を表示する。走査全体は止めない |
| シンボル抽出の失敗 | 該当ファイルのシンボルと依存を空として続行する |

## ビジュアル

世界観は B. Constellation。ほぼ黒の宇宙に、紫の主色と青緑の差し色を置く。
モックアップは `.superpowers/brainstorm/` の `visual-direction.html` を出発点とする。

- コードは等幅、UI は Hiragino Sans を基本とする。必要な書体はアプリに同梱する。
- 動きには意味を持たせる。カメラ移動はツアーの現在地を伝え、星座が灯る演出は解析の完了を伝える。
- 「視差効果を減らす」の設定を尊重し、有効ならカメラ移動と演出を短いフェードに置き換える。
- 全操作をキーボードで行えるようにし、本文のコントラスト比は 4.5:1 以上にする。

## テスト

- `core`: 小さな固定リポジトリを使った走査、シンボル、依存、配置の決定性のテスト。
- `ai`: 偽の `claude` スクリプトを使った引数、進捗、検証、再試行のテスト。モデル選択ごとの `--model` の有無も確認する。
- セキュリティ: 上記の検証項目を、実際の `claude` を使う手動実行の結合テストとして用意する。
- `app`: 操作ロジックは gpui のテストコンテキストで確認し、見た目はセルフチェックで確認する。

## 品質基準

### 性能目標（M1 で実測する）

| 指標 | 目標 |
|---|---|
| コールドスタート | 500 ms 未満 |
| 1 万ファイルの集計 | 10 秒未満 |
| 星図とコードのスクロール | 60 fps を維持 |
| `.app` のサイズ | 40 MB 未満 |
| 表示中のメモリ | 200 MB 未満 |

### デザインのセルフチェック

1. デモ用の起動モードで主要な状態（初回、登録直後、解析中、完了、ツアー、コード、検索、エラー）を開き、撮影する。
2. Awwwards の配点（デザイン 40、使いやすさ 30、独創性 20、内容 10）で採点し、問題点と根拠を記録する。動きはフレーム連番で確認する。
3. 文脈を持たない別のエージェントにも同じ画像で採点させる。
4. 両者の採点がすべての軸で 8/10 以上になるまで改善を繰り返す。

この基準は自己評価であり、受賞を保証するものではない。Awwwards と FWA は主に Web サイトが対象なので、評価軸を借りて用いる。
